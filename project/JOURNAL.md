# Журнал проекта: траектории отзывов Steam-игр

Курс: «Имитационное и статистическое моделирование». Этот файл ведётся по ходу работы: что решили, что получили, как воспроизвести. Таблицы с результатами не переписываются сюда вручную, их строит `summarize_results.py` в `results/model_summary.md`.

Статус на 2026-10-16: данные подготовлены, подогнано восемь моделей, сравнение завершено. Дальше: типы траекторий, отчёт, презентация, визуализации.

## 1. Постановка

**Вопрос.** Как описать поток отзывов на игру после выхода несколькими конкурирующими моделями и насколько симуляции этих моделей похожи на реальные игры?

**Как мы к нему пришли.** Исходная спека `steam_lifecycle_project_spec.md` была написана LLM без просмотра данных. Данные показали, что часть её плана неосуществима (см. п. 2), поэтому проект перестроен. Спека больше не обязательна.

**Критерий «главной проверки»** (решение автора): свободная имитация, а не только правдоподобие. Причина: курс про имитационное моделирование, а правдоподобие для моделей с памятью использует реальные прошлые недели.

## 2. Данные

| Источник | Что в нём | Статус |
|---|---|---|
| Anton, `datasets/kaggle/antonkozyriev-game-recommendations-on-steam` | `games.csv` 50 872 игры (даты релиза 1997–2023); `recommendations.csv` 41 154 794 отзыва с 2010-10-15 по 2022-12-31 для 37 610 игр | **основной источник** |
| Mendeley, `datasets/mendeley` | 2000 приложений (1851 игра), число игроков каждые 5 минут, дек. 2017 – авг. 2020; только 69 игр вышли внутри окна записи | изучен, в моделях не используется (у большинства игр не наблюдается начало жизни) |
| najzeko, `datasets/kaggle/najzeko-steam-reviews-2021` | 8 ГБ отзывов ~300 популярных игр до янв. 2021 | не профилирован |

Факты, влияющие на выводы:
- Медиана числа отзывов на игру 39; ≥200 отзывов у 8928 игр, ≥1000 у 3685. Это отбор по популярности: выводы относятся к играм с достаточным числом отзывов.
- Mendeley: файл `applicationInformation.csv` в кодировке cp1252, у 146 игр дата релиза не разобралась.
- Отзывы не равны игрокам: доля игроков, пишущих отзывы, зависит от жанра и аудитории.

| Решение | Кто | Причина |

| Ограничение силы эха Хокса (η ≤ 0,8 и 0,5) и два способа подгонки толчков | автор | проверить, лечит ли ограничение нестабильность симуляции |

## 4. Пайплайн

Запуск из корня проекта, порядок обязателен:

```
python build_weekly_series.py --data-dir datasets/kaggle/antonkozyriev-game-recommendations-on-steam
python fit_decay.py
python fit_hawkes.py
python fit_shocks.py
python check_fits.py
python summarize_results.py
```

| `fit_shocks.py` | weekly_series, fits_hawkes | `fits_shocks.csv` | поверх `hawkes50` случайные толчки: `shock_rule` (правило) и `shock_joint` (скрытые переменные) |

## 5. Модели

Счёт отзывов за неделю везде отрицательное биномиальное (дисперсия `μ + μ²/r`), `t` недели с первого отзыва.

| Модель | Среднее на неделе t | Параметры (с `r`) |
|---|---|---|
| exp | `A·exp(−λt)` | 3 |
| power | `A·(1+t)^(−α)` | 3 |
| lognormal | `A·exp(−(ln(1+t) − μ)² / 2σ²)` (форма кривой, не плотность) | 4 |
| hawkes | `B·(1+t)^(−α) + η·s_t`, `s_t` затухающая сумма прошлых недель, η ≤ 0,99 | 5 |
| hawkes80, hawkes50 | то же с η ≤ 0,8 и ≤ 0,5 | 5 |
| shock_rule, shock_joint | `hawkes50` + с вероятностью `p` каждую неделю толчок лог-нормального размера | 8 |

При η = 0 Хокс равен степенному закону, при p → 0 модели с толчками равны `hawkes50`. Это использовалось для проверки подгонки.

## 6. Результаты

### 6.1 Форма реальных рядов
Среди 5311 основных игр с полным окном 104 недели (по 4-недельной сумме): пик в первые 8 недель у 69%, позже 26-й недели у 23%, позже года у 13%. Игры с «двумя режимами» (например, 765410: тишина до 44-й недели, затем 448 отзывов за неделю при релизном уровне около 12) простые кривые описать не могут.

### 6.2 Что получилось на каждом шаге
- **Три простые модели.** Степенной закон лучше по AIC у 82,6% игр, но все три плохо передают первый всплеск (картинка `figures/example_fits.png`), автокорреляция остатков 0,26–0,32.
- **Хокс.** По AIC выигрывает у 66% игр, автокорреляция остатков падает до 0,04. У 9% игр η упирается в верхнюю границу 0,99, у четверти игр эхо живёт около недели.
- **Ширина коридоров.** Низкая доля «вне коридора» у Хокса частично куплена шириной: его 95%-коридоры на 20–65% шире.
- **CRPS.** Единой лучшей модели нет: по доле отзывов на старте лучший Хокс, по неделе пика и неделе 50% отзывов логнормальная, по общему числу отзывов экспонента. Подробности и разбивка по ранним и поздним пикам в `results/model_summary.md`.
- **Ограничение η.** Помогает частично (общее число 0,092 → 0,083 → 0,072 при η ≤ 0,99 / 0,8 / 0,5), не отнимая выигрыша на старте, но степенной закон по общему числу (0,055) остаётся лучше.
- **Толчки.** Помогают только играм с поздним пиком (23% выборки) и ухудшают остальные. Коридоры по неделе пика 86–88 недель против 26 у `hawkes50`. `shock_joint` выигрывает по AIC у 56% игр, но хуже `shock_rule` в имитации: подбирает в среднем около 4 мелких толчков на игру (размер порядка 5 отзывов), то есть использует их как лишний шум.

### 6.3 Типы траекторий (5309 основных игр с полным окном; `processed/cluster_output.txt`)
Описания игры двух семейств: по всем 104 неделям (`shape`, `summary`, `params`) и по «будущему», неделям 12–103 (`shape_f`, `summary_f`, `params_f`; для параметров Хокс `hawkes50` подгоняется заново только по неделям с 12-й). Только «будущее» годится для честной проверки предсказуемости по первым 12 неделям. Предыдущая версия скрипта строила типы по всем неделям и поэтому завышала предсказуемость (macro-F1 0,77 при k = 2 против базовой 0,39 отчасти тавтология: первые недели входят в определение типа). Копия старых результатов в `processed/old/`.

- **Предсказуемость по неделям 0–11 (без утечки, k-means).** Форма: k = 2 даёт 0,57 против базовой 0,34, при k = 3 уже 0,23 против 0,22, то есть почти нет выигрыша. Сводные: k = 2 0,43 против 0,37, но k = 4–6 0,35/0,27/0,27 против 0,14/0,10/0,07. Параметры: k = 3–5 0,38/0,29/0,30 против 0,26/0,15/0,09. Абсолютные значения невелики (0,2–0,4), выигрыш над базовой в 2–3 раза при k ≥ 4 у сводных и параметров.
- **Контроль без структуры** (гауссовы данные с теми же средними и ковариациями, k-means, то же пространство). Форма из будущего неотличима от шума: silhouette 0,085 против 0,082 (k = 2), устойчивость 0,94 против 0,94; PCA: первая компонента объясняет 14%, для 90% нужно 18 из 23 компонент. Форма по всем неделям почти одномерна (первая компонента 55%: «доля отзывов на старте»). Сводные из будущего слабо выше контроля (silhouette 0,32 против 0,31 при k = 2, 0,26 против 0,21 при k = 4). У параметров silhouette в 1,4–2 раза выше контроля, но см. следующий пункт.
- **Параметры и границы подгонки.** Только 26% (по всем неделям) и 30% (по будущему) игр имеют `η` и `ρ` строго внутри допустимого диапазона, остальные на границе. Кластеры по параметрам во многом отражают скопление подгонок на границах (отсюда выброс-кластер около 5%), а не траектории. Без граничных игр устойчивость падает (0,57–1,0 по k), согласие со сводными ARI 0,07–0,22.
- **Согласие между описаниями из будущего.** При k = 2 ARI форма/сводные 0,55, форма/параметры 0,39, сводные/параметры 0,38. При k ≥ 5 для k-means ARI 0,03–0,22: мелкие типы не переносятся между описаниями. Описание по всем неделям и по будущему согласуются плохо (ARI 0,03–0,21).
- **Внешняя проверка.** Связь типа с первым тегом слабая (V Крамера 0,06–0,15 для описаний из будущего), с ценой и рейтингом почти нулевая (ε² ≤ 0,05).
- **Итог.** Устойчиво выделяется только грубое деление на две группы (по доле отзывов на старте, при построении по всем неделям; по будущему слабо). Более мелкие «типы траекторий» данные не поддерживают: форма будущего не отличается от шума, параметры упираются в границы, внешние данные типы не объясняют. Формулировка для отчёта: типы в духе спеки (хайп, устойчивая, возвращение) на этих данных не подтверждаются. Названия типов давать только для k = 2 и с оговорками.

### 6.4 Главный вывод (формулировка для отчёта)
Ни одна из восьми моделей не лучше остальных по всем характеристикам. Правдоподобие и свободная имитация дают разные рейтинги: модели с памятью лучше «объясняют» наблюдённые ряды, но хуже порождают новые траектории, потому что случайные отклонения накапливаются.

## 7. Ограничения (для раздела отчёта)

- Отзывы не равны игрокам; отбор игр по числу отзывов (≥200) смещает выборку к популярным.
- В параметрах подгонки неопределённость не учитывается: имитация чуть оптимистична.
- Размер ансамбля 200: оценки CRPS слегка шумные.
- Разбиение на игры с ранним и поздним пиком сделано по наблюдённому пику, то есть по исходу; годится для диагностики, не для предсказания.
- `shock_rule` определяет толчки той же моделью, которую проверяет; параметр `r` базового Хокса частично поглощает всплески.
- Подгонка и проверка идут на одних и тех же играх (нет отложенной выборки), внешней проверки на другом наборе (najzeko) и на числе игроков (Mendeley) пока нет.
- AIC моделей с памятью использует реальные прошлые недели и не сравним по смыслу с AIC простых кривых.
- Первый уровень сравнения (оценка каждой недели по отдельности) только упомянут, не посчитан.
- Модели описывают только число отзывов; причины всплесков (акции, обновления) в данных отсутствуют.
- Mendeley в моделях не используется; его проблемы (кодировка cp1252, 146 неразобранных дат релиза) нужно будет решить, если он пойдёт в проверку по числу игроков.
